# System Boundary Interface Documentation

This document describes the system's external invocation interfaces, including CLI commands, API endpoints, configuration parameters, and other boundary mechanisms.

## Command Line Interface (CLI)

### dotnet run --project src/DocumentConverter.Web

**Description**: Primary executable entry point for EConverter.Web. Builds the WebApplicationBuilder, registers services for all nine feature areas, configures the EF Core/Npgsql DbContext, health checks, OpenTelemetry, authentication/authorization and the Blazor/Radzen pipeline, then starts the HTTP listener and hosted background services (JobProcessorWorker, DocumentIndexingWorker).

**Source File**: `src/DocumentConverter.Web/Program.cs`

**Arguments**:

- `args` (string[]): optional - Command-line arguments forwarded by top-level statements; standard host arguments switch the environment (--environment Development) or override configuration keys (--ConnectionStrings:DefaultConnection=...).

**Options**:

- `--environment, -e`(string): optional - ASP.NET Core environment name; controls whether InitializeDatabaseAsync applies migrations or EnsureCreated and gates developer exception pages. (default: `Production`)
- `--urls`(string): optional - Kestrel binding URLs for the web host. (default: `http://localhost:5000`)
- `--ConnectionStrings:DefaultConnection`(string): optional - Overrides the database connection string supplied in appsettings.json. (default: `Server=localhost,1433;Database=...;User Id=sa;Password=***`)

**Usage Examples**:

```bash
dotnet run --project src/DocumentConverter.Web --environment Development
```

```bash
dotnet run --project src/DocumentConverter.Web --urls http://0.0.0.0:8080
```

```bash
docker run -p 8080:8080 -e ASPNETCORE_ENVIRONMENT=Production econverter-web
```

### dotnet run --project src/Workers/DocumentWorker

**Description**: Standalone BackgroundService microservice. Host.CreateApplicationBuilder wires EF Core contexts, encrypted storage, OCR and conversion services, notification services and the hosted Worker; ConsoleJobNotificationService writes job progress/completion/failure/cancellation/batch updates to the logger as the headless stand-in for SignalR notifications.

**Source File**: `src/Workers/DocumentWorker/Program.cs`

**Options**:

- `--environment, -e`(string): optional - Host environment name controlling configuration layering for the worker. (default: `Production`)
- `RabbitMQ:Enabled`(boolean): optional - Toggles RabbitMQ consumption; when false the worker falls back to its polling loop over ProcessingJob state. (default: `false`)
- `DOCUMENT_STORAGE_ROOT`(string): optional - Filesystem root for the worker's document storage reads and writes. (default: `./app_data/storage (web) / Windows path (worker appsettings)`)

**Usage Examples**:

```bash
dotnet run --project src/Workers/DocumentWorker
```

```bash
dotnet run --project src/Workers/DocumentWorker --RabbitMQ:Enabled=true
```

### docker build -f src/DocumentConverter.Web/Dockerfile -t econverter-web .

**Description**: Deployment contract for the whole application. Multi-stage .NET 10 SDK build that copies global.json, Directory.Build.props and Directory.Packages.props first, then each referenced .csproj individually before restore — deliberate layer-cache optimization so NuGet restore is invalidated only when project references change.

**Source File**: `src/DocumentConverter.Web/Dockerfile`

**Options**:

- `--build-arg ASPNETCORE_ENVIRONMENT`(string): optional - Environment baked into the runtime image. (default: `Production`)

**Usage Examples**:

```bash
docker build -f src/DocumentConverter.Web/Dockerfile -t econverter-web:latest .
```

```bash
docker run -d -p 8080:8080 --env-file .env econverter-web:latest
```

## API Interfaces

### GET /api/documents

**Description**: Lists documents visible to the authenticated caller, including folder association and paging over the document aggregate.

**Source File**: `src/DocumentConverter.Web/Endpoints/DocumentEndpoints.cs`

**Request Format**: Query string parameters (folderId, paging, filters)

**Response Format**: application/json — document list DTOs

**Authentication**: ASP.NET Core cookie / Blazor Server session (group-level RequireAuthorization)

### POST /api/documents

**Description**: Uploads a document (multipart/form-data or stream), persists it through the storage abstraction, records hashing and version metadata, and optionally enqueues a processing job.

**Source File**: `src/DocumentConverter.Web/Endpoints/DocumentEndpoints.cs`

**Request Format**: multipart/form-data (file stream + metadata) or application/octet-stream

**Response Format**: application/json — created document DTO / 201

**Authentication**: ASP.NET Core cookie / Blazor Server session (RequireAuthorization)

### GET /api/documents/{id}

**Description**: Downloads a document by identifier; streams bytes from the encrypted storage layer and falls back to in-process DOCX-to-PDF conversion when a PDF rendition is requested.

**Source File**: `src/DocumentConverter.Web/Endpoints/DocumentEndpoints.cs`

**Request Format**: Path parameter {id}: Guid; optional query flags (format, inline)

**Response Format**: application/pdf or application/octet-stream (binary stream)

**Authentication**: ASP.NET Core cookie / Blazor Server session (RequireAuthorization) with ownership enforcement in the Document aggregate

### POST /api/documents/{id}/rename

**Description**: Renames a document using the RenameDocumentRequest record contract.

**Source File**: `src/DocumentConverter.Web/Endpoints/DocumentEndpoints.cs`

**Request Format**: application/json — RenameDocumentRequest { NewName: string }

**Response Format**: application/json — updated document DTO

**Authentication**: ASP.NET Core cookie / Blazor Server session (RequireAuthorization)

### POST /api/documents/{id}/move

**Description**: Moves a document into another folder (or to the root when FolderId is null) using the MoveDocumentRequest contract.

**Source File**: `src/DocumentConverter.Web/Endpoints/DocumentEndpoints.cs`

**Request Format**: application/json — MoveDocumentRequest { FolderId: Guid? }

**Response Format**: application/json — updated document DTO

**Authentication**: ASP.NET Core cookie / Blazor Server session (RequireAuthorization)

### DELETE /api/documents/{id}

**Description**: Deletes a document, transitioning lifecycle state and removing the stored object through the storage abstraction.

**Source File**: `src/DocumentConverter.Web/Endpoints/DocumentEndpoints.cs`

**Request Format**: Path parameter {id}: Guid

**Response Format**: 204 No Content / 404 Not Found

**Authentication**: ASP.NET Core cookie / Blazor Server session (RequireAuthorization)

### POST /api/documents/folders

**Description**: Creates a folder, optionally nested under a parent folder, using the CreateFolderRequest contract.

**Source File**: `src/DocumentConverter.Web/Endpoints/DocumentEndpoints.cs`

**Request Format**: application/json — CreateFolderRequest { Name: string, ParentFolderId: Guid? }

**Response Format**: application/json — created folder DTO

**Authentication**: ASP.NET Core cookie / Blazor Server session (RequireAuthorization)

### POST /api/documents/folders/{id}/rename

**Description**: Renames an existing folder using the RenameFolderRequest contract.

**Source File**: `src/DocumentConverter.Web/Endpoints/DocumentEndpoints.cs`

**Request Format**: application/json — RenameFolderRequest { Name: string }

**Response Format**: application/json — updated folder DTO

**Authentication**: ASP.NET Core cookie / Blazor Server session (RequireAuthorization)

### DELETE /api/documents/folders/{id}

**Description**: Deletes a folder and applies the configured policy for contained documents and child folders.

**Source File**: `src/DocumentConverter.Web/Endpoints/DocumentEndpoints.cs`

**Request Format**: Path parameter {id}: Guid

**Response Format**: 204 No Content / 409 Conflict

**Authentication**: ASP.NET Core cookie / Blazor Server session (RequireAuthorization)

### GET/POST /api/documents (intelligence sub-routes)

**Description**: AI document intelligence surface: automated categorization, summary generation and key-entity extraction. Merges into the existing /api/documents group, so route registration order relative to DocumentEndpoints.cs is a collision concern.

**Source File**: `src/DocumentConverter.Web/Endpoints/DocumentIntelligenceEndpoints.cs`

**Request Format**: application/json — DocumentConverter.Contracts.AI request DTOs

**Response Format**: application/json — AI insight/summary/entity DTOs

**Authentication**: ASP.NET Core cookie / Blazor Server session (group-level RequireAuthorization)

### GET/POST /api/editor/...

**Description**: Editor gateway serving inline PDF byte streams for the client viewer and handling edit operations (page structure, annotations, redaction) against Application.Editor.

**Source File**: `src/DocumentConverter.Web/Endpoints/EditorEndpoints.cs`

**Request Format**: Path/query identifiers plus Contracts.Editor DTOs

**Response Format**: application/pdf (inline stream) or application/json — editor operation results

**Authentication**: ASP.NET Core cookie / Blazor Server session (group-level RequireAuthorization)

### GET/POST /api/processing/...

**Description**: Submits document processing jobs and retrieves job results/status. The only endpoint group using a named authorization policy rather than parameterless RequireAuthorization, making it the reference pattern for policy-based access control.

**Source File**: `src/DocumentConverter.Web/Endpoints/ProcessingEndpoints.cs`

**Request Format**: application/json — Contracts.Processing job submission DTOs

**Response Format**: application/json — job/result DTOs

**Authentication**: Named authorization policy "RequireUser"

### POST /account/login

**Description**: Form-based credential ingestion via ASP.NET Core Identity SignInManager/UserManager. The only unauthenticated-by-design group; UrlIsValid() guards the post-login returnUrl against open-redirect abuse.

**Source File**: `src/DocumentConverter.Web/Endpoints/AccountEndpoints.cs`

**Request Format**: application/x-www-form-urlencoded — [FromForm] email, password, returnUrl

**Response Format**: HTTP 302 redirect (validated local URL) or re-rendered login form with validation errors

**Authentication**: None (public credential entry point); issues Identity authentication cookie on success

### POST /account/logout (session transition endpoints)

**Description**: Sign-out and account session transitions handled through the same /account route group and Identity sign-in manager.

**Source File**: `src/DocumentConverter.Web/Endpoints/AccountEndpoints.cs`

**Request Format**: application/x-www-form-urlencoded

**Response Format**: HTTP 302 redirect

**Authentication**: ASP.NET Core Identity cookie (sign-out of an existing session)

### WebSocket / SignalR /_blazor (SignalR circuit hub) and job notification hub

**Description**: Persistent SignalR circuit carrying Blazor Server interactivity and job progress/completion/failure notifications published by JobNotificationService into the Hubs directory.

**Source File**: `src/DocumentConverter.Web/Program.cs; src/DocumentConverter.Web/Hubs; src/DocumentConverter.Web/Services/JobNotificationService.cs`

**Request Format**: SignalR negotiate + WebSocket frames (JSON protocol)

**Response Format**: SignalR frames — job progress, completion, failure, cancellation, batch update events

**Authentication**: ASP.NET Core cookie (authenticated circuit)

### GET /health (health check endpoints)

**Description**: Liveness/readiness endpoints registered in Program.cs, including EF Core DbContext health checks used by container orchestration and load balancers.

**Source File**: `src/DocumentConverter.Web/Program.cs`

**Request Format**: None

**Response Format**: text/plain (Healthy/Degraded/Unhealthy) or JSON health report

**Authentication**: Typically anonymous or infrastructure-scoped (configured in Program.cs)

### POST (HTTP/HTTPS, streaming) Outbound: External AI provider completions (OpenAI / Gemini / Claude / local LLM)

**Description**: Central outbound AI gateway. Builds provider-specific requests with headers and timeouts, and normalizes OpenAI choices/deltas, Gemini element chunks, and Claude SSE frames (including error frames) into ExternalAiStreamChunk objects. Opt-in cloud counterpart to zero-egress local intelligence.

**Source File**: `src/DocumentConverter.Infrastructure/AI/ExternalAiClient.cs; src/DocumentConverter.Application/AI/IExternalAiClient.cs`

**Request Format**: application/json — provider-specific prompt payloads

**Response Format**: application/json or text/event-stream (SSE/NDJSON) — normalized to IAsyncEnumerable<ExternalAiStreamChunk>

**Authentication**: Provider API key / bearer token supplied through configuration (IExternalAiClient)

### TCP (Npgsql protocol) Outbound: PostgreSQL via Npgsql/EF Core

**Description**: Single AppDbContext covering both Identity tables and the domain schema. DatabaseExtensions.AddConfiguredDbContext selects the provider; InitializeDatabaseAsync applies migrations/EnsureCreated and performs to_regclass existence checks before seeding.

**Source File**: `src/DocumentConverter.Infrastructure/Persistence/DatabaseExtensions.cs`

**Request Format**: Npgsql wire protocol — EF Core generated SQL / migrations

**Response Format**: Npgsql result sets

**Authentication**: Connection-string credentials (appsettings DefaultConnection)

### AMQP (publish/subscribe) Outbound: RabbitMQ job dispatch

**Description**: Publishes JobMessage payloads from the application layer to conversion workers; the web host falls back to NoOpQueuePublisher and the worker degrades to a polling loop when the consumer is disabled. Broker is an accelerator, not a hard dependency.

**Source File**: `src/DocumentConverter.Infrastructure/Messaging; src/Workers/DocumentWorker/Program.cs`

**Request Format**: AMQP message body — Contracts.Messages JobMessage

**Response Format**: AMQP ack/nack (consumer-side)

**Authentication**: Broker credentials via configuration (RabbitMQ section)

### HTTPS (OIDC / OAuth 2.0) Outbound: Microsoft Entra ID (OIDC)

**Description**: Federated authentication alongside local accounts. The User aggregate records AuthenticationType (Local or EntraId) while authorization keys on the internal stable entity ID rather than the external subject claim.

**Source File**: `src/DocumentConverter.Web/Authentication; src/DocumentConverter.Domain/Identity`

**Request Format**: OIDC authorize/token requests

**Response Format**: ID token / access token (JWT)

**Authentication**: OpenID Connect authorization code flow / token validation

## Integration Suggestions

### HTTP / Minimal API (REST)

Programmatic integration against the /api/documents, /api/processing and /api/editor groups. All groups except /account require authentication; /api/processing is the reference policy-based boundary using the named "RequireUser" policy. Note that DocumentEndpoints.cs and DocumentIntelligenceEndpoints.cs both create /api/documents groups, so route ordering and collisions must be verified against the running host before relying on sub-paths.

**Example Code**:

```
curl -X POST https://econverter.example.com/api/documents \
  -H "Cookie: .AspNetCore.Identity.Application=<session>" \
  -F "file=@contract.docx" \
  -F "folderId=3f2b9c1e-..."

# Submit a processing job under the RequireUser policy
curl -X POST https://econverter.example.com/api/processing \
  -H "Cookie: .AspNetCore.Identity.Application=<session>" \
  -H "Content-Type: application/json" \
  -d '{"documentId":"3f2b9c1e-...","targetFormat":"pdf","enableOcr":true}'
```

**Best Practices**:

- Authenticate through /account/login to obtain the Identity cookie, or negotiate a bearer mechanism deliberately rather than reusing browser cookies in service-to-service code.
- Always validate that returnUrl is local before redirecting; the server-side UrlIsValid() guard exists precisely because this boundary is open-redirect sensitive.
- Expect binary streams (application/pdf, application/octet-stream) from download and editor endpoints — do not assume JSON.
- Treat endpoint-level authorization as per-group: /api/documents and /api/editor use parameterless RequireAuthorization(), /api/processing uses the RequireUser policy. Verify the policy maps to the intended claim/role in your installation.
- Prefer job submission plus SignalR/notification polling over long-blocking synchronous conversion for large files.

### SignalR / WebSocket

Real-time job progress and completion events published by JobNotificationService into the Hubs directory, consumed by the Blazor UI and available to external dashboards that negotiate an authenticated circuit.

**Example Code**:

```
const connection = new signalR.HubConnectionBuilder()
  .withUrl("https://econverter.example.com/hubs/jobs", { withCredentials: true })
  .withAutomaticReconnect()
  .build();

connection.on("JobProgress", (jobId, percent) => console.log(jobId, percent));
connection.on("JobCompleted", (jobId, docId) => console.log("done", docId));
await connection.start();
```

**Best Practices**:

- Reuse the same authenticated cookie context as the web UI; the hub is not an anonymous stream.
- Implement reconnect logic — the notification stream is an accelerator, not the source of truth. Always reconcile against /api/processing state.
- Do not expose the hub endpoint to untrusted origins without an explicit CORS/origin policy.

### Outbound AI provider gateway (IExternalAiClient)

Integrate additional LLM providers by implementing IExternalAiClient and normalizing their streaming payloads into ExternalAiStreamChunk(ReasoningDelta, ContentDelta). The existing ExternalAiClient demonstrates OpenAI, Gemini and Claude parsing including SSE error frames, keeping provider SDKs behind one application-layer contract.

**Example Code**:

```
public sealed class MyProviderAiClient : IExternalAiClient
{
    public async IAsyncEnumerable<ExternalAiStreamChunk> SynthesizeAnswerAsync(
        string prompt, [EnumeratorCancellation] CancellationToken ct)
    {
        await foreach (var raw in _http.StreamAsync(prompt, ct))
        {
            yield return new ExternalAiStreamChunk(
                ReasoningDelta: raw.Thinking,
                ContentDelta: raw.Text);
        }
    }
}
```

**Best Practices**:

- Keep the reasoning/content split — ReasoningDelta must never be surfaced as user-visible answer text.
- Handle provider SSE error frames explicitly; silent stream termination is indistinguishable from a truncated answer.
- Register the implementation only when cloud egress is policy-permitted; core intelligence (BM25, HNSW, RAG) must remain functional with no external provider configured.
- Apply per-provider timeouts and cancellation propagation through the CancellationToken.

### Queue-based worker scaling (RabbitMQ)

Enable RabbitMQ:Enabled in the worker configuration to switch from the polling fallback to broker-driven consumption of Contracts.Messages JobMessage payloads. The web host publishes through the queue abstraction with a NoOpQueuePublisher fallback, so scaling is additive rather than a hard dependency.

**Example Code**:

```
# Scale out workers against the shared broker
for i in 1 2 3; do
  docker run -d --name worker-$i \
    -e RabbitMQ__Enabled=true \
    -e RabbitMQ__Host=rabbitmq \
    -e ConnectionStrings__DefaultConnection="$PG_CONN" \
    econverter-worker:latest
done
```

**Best Practices**:

- Keep the polling loop enabled in at least one deployment path so a broker outage degrades rather than halts processing.
- Workers share the PostgreSQL lease-based ProcessingJob state machine; do not add a second scheduling authority outside it.
- Size worker concurrency against OCR/Tesseract native memory, not CPU count alone.

### Configuration / environment variables

Startup configuration boundaries: ConnectionStrings:DefaultConnection, Storage:RootPath, ClamAV toggling, AllowedHosts, RabbitMQ:Enabled and per-namespace Logging levels. Both appsettings.json files currently ship a literal 'sa' credential against localhost SQL Server — the highest-risk configuration surface in the solution.

**Example Code**:

```
{
  "ConnectionStrings": {
    "DefaultConnection": "Host=db;Database=econverter;Username=app;Password=${PG_PASSWORD}"
  },
  "Storage": { "RootPath": "/var/lib/econverter/storage" },
  "ClamAV": { "Enabled": true },
  "RabbitMQ": { "Enabled": true, "Host": "rabbitmq" },
  "AllowedHosts": "econverter.example.com"
}
```

**Best Practices**:

- Replace the inline sa credential with a least-privilege application role injected from a secret store; never commit a production connection string.
- Narrow AllowedHosts from the wildcard to the actual hostnames to prevent host-header abuse.
- Enable ClamAV scanning in any deployment that accepts untrusted uploads.
- Keep the provider selection explicit in AddConfiguredDbContext — PostgreSQL-specific to_regclass checks silently change behavior across providers.
- Set DatabaseExtensions initialization to migrations in production and EnsureCreated only in development.
