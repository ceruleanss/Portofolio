# System Boundary Interface Documentation

This document describes the system's external invocation interfaces, including CLI commands, API endpoints, configuration parameters, and other boundary mechanisms.

## Command Line Interface (CLI)

### ./DocumentConverter.Web (Kestrel web host, no custom CLI arguments)

**Description**: The web host is started as a plain ASP.NET Core WebApplication with no custom command-line argument parsing. Its startup interface is therefore the ASP.NET Core environment contract: the ASPNETCORE_ENVIRONMENT variable selects appsettings.{Environment}.json, and standard hosting variables (ASPNETCORE_URLS, ASPNETCORE_HTTP_PORTS) control binding. DOTNET_ENVIRONMENT applies to the worker's generic host.

**Source File**: `./src/DocumentConverter.Web/Program.cs, ./src/DocumentConverter.Web/appsettings.json`

**Options**:

- `ASPNETCORE_ENVIRONMENT`(string): optional - Selects the configuration overlay (appsettings.Development.json vs appsettings.json) and dev-only behaviors such as LocalDB connection strings and reduced log verbosity. (default: `Production`)
- `ASPNETCORE_URLS`(string): optional - Kestrel binding addresses for the web host (or container-exposed port). (default: `http://localhost:5000`)
- `AllowedHosts`(string): optional - Host header allow-list enforced by HostFiltering middleware; declared in appsettings.json as '*'. Should be narrowed in production to prevent host-header based attacks. (default: `*`)

**Usage Examples**:

```bash
ASPNETCORE_ENVIRONMENT=Development dotnet run --project src/DocumentConverter.Web
```

```bash
docker run -e ASPNETCORE_ENVIRONMENT=Production -e ConnectionStrings__DefaultConnection='...' econverter-web
```

### ./DocumentWorker (generic host background service, no custom CLI arguments)

**Description**: The worker bootstraps Host.CreateApplicationBuilder, registers EF Core persistence, OCR, storage encryption, messaging and processing services, and registers Worker as a hosted service. Its startup surface is configuration-driven (appsettings.json / appsettings.Development.json plus environment-variable overrides). ConsoleJobNotificationService writes job progress, completion, failure, cancellation and batch updates to the console logger.

**Source File**: `./src/Workers/DocumentWorker/Program.cs, ./src/Workers/DocumentWorker/appsettings.json, ./src/DocumentConverter.Infrastructure/Messaging/RabbitMqOptions.cs`

**Options**:

- `DOTNET_ENVIRONMENT`(string): optional - Selects the configuration overlay for the generic host (appsettings.Development.json switches to (localdb)\mssqllocaldb and raises EF Core log threshold to Warning). (default: `Production`)
- `ConnectionStrings:DefaultConnection`(string): required - SQL Server connection string used by EF Core persistence for job leases, batches, attempts and document metadata. Override via ConnectionStrings__DefaultConnection. (default: `Server=localhost,1433;Database=...;User Id=sa;Password=... (placeholder in appsettings.json)`)
- `RabbitMQ:Enabled`(boolean): optional - Enables AMQP consumption from the broker. When disabled, the NoOpQueuePublisher fallback is used and the worker relies on the in-process JobProcessorWorker dequeue path. (default: `false`)
- `RabbitMQ:Host`(string): optional - Broker hostname for the document.processing queue / document exchange. (default: `localhost`)
- `RabbitMQ:Port`(integer): optional - AMQP broker port. (default: `5672`)
- `RabbitMQ:UserName`(string): optional - AMQP username. Credentials are stored in plain configuration, making this a security-sensitive surface; inject via secret storage in production. (default: `guest`)
- `RabbitMQ:Password`(string): optional - AMQP password. Must be supplied from environment variables or secret storage in production. (default: `guest`)
- `RabbitMQ:QueueName`(string): optional - Queue carrying JobMessage payloads from the web host to the worker. (default: `document.processing`)
- `RabbitMQ:ExchangeName`(string): optional - Exchange used by the message dispatcher for routing job payloads. (default: `document`)

**Usage Examples**:

```bash
dotnet run --project src/Workers/DocumentWorker
```

```bash
RabbitMQ__Enabled=true RabbitMQ__Host=rabbitmq ConnectionStrings__DefaultConnection='...' dotnet DocumentWorker.dll
```

### Configuration-driven startup interface (shared across Web and Worker)

**Description**: Both hosts are configured exclusively through appsettings.json overlays and environment-variable overrides bound with the ASP.NET Core options pattern. The following keys constitute the effective command-line-equivalent startup contract for the platform.

**Source File**: `./src/DocumentConverter.Web/appsettings.json, ./src/DocumentConverter.Infrastructure/Security/StorageEncryption/StorageEncryptionOptions.cs, ./src/Workers/DocumentWorker/appsettings.json`

**Options**:

- `Storage:RootPath`(string): optional - Filesystem root into which encrypted document envelopes are written and from which the worker streams inputs and outputs. Also surfaced to the worker as DOCUMENT_STORAGE_ROOT. (default: `./app_data/storage`)
- `DOCUMENT_STORAGE_ROOT`(string): optional - Environment variable consumed at worker startup to locate the local document storage root for the conversion pipeline. (default: `configured path in appsettings.json`)
- `Storage:Encryption:Enabled`(boolean): optional - Binds from section Storage:Encryption and drives IsEncryptionEnabled. Getting this wrong silently disables at-rest AES-256-GCM envelope encryption. (default: `false`)
- `Storage:Encryption:MasterKey`(string (Base64, 256-bit)): required - Base64-encoded 256-bit Master Key Encryption Key (KEK) used to wrap per-document DEKs. Production key material is expected to be injected via environment variable or secret storage, never checked into configuration. (default: `none (must be supplied in production)`)
- `ClamAV:Enabled`(boolean): optional - Controls whether uploaded documents are scanned by the ClamAV anti-virus integration before storage. (default: `false`)
- `Logging:LogLevel:*`(string): optional - Per-category log verbosity for the host and worker. (default: `Information (Default), Warning (Microsoft.AspNetCore / Microsoft.EntityFrameworkCore in Development)`)

**Usage Examples**:

```bash
Storage__Encryption__Enabled=true Storage__Encryption__MasterKey='<base64-256bit>' dotnet DocumentConverter.Web.dll
```

```bash
DOCUMENT_STORAGE_ROOT=/var/lib/econverter/storage dotnet DocumentWorker.dll
```

## API Interfaces

### GET, POST, PUT, DELETE /api/documents

**Description**: Core document and folder management route group registered by MapDocumentEndpoints. Serves the primary product capability: document listing, upload, download, rename, move, delete and hierarchical folder operations. Uploaded DOCX streams can be converted to PDF in-process via ConvertDocxStreamToPdf (OpenXml -> PdfSharp). Handlers delegate to Application.Documents use cases and return Contracts.Documents DTOs.

**Source File**: `./src/DocumentConverter.Web/Endpoints/DocumentEndpoints.cs`

**Request Format**: application/json (RenameDocumentRequest{NewName}, MoveDocumentRequest{FolderId}, CreateFolderRequest{Name,ParentFolderId}, RenameFolderRequest{Name}) and multipart/form-data for document upload

**Response Format**: application/json (Contracts.Documents DTOs) and application/pdf for converted output streams

**Authentication**: ASP.NET Core Identity cookie authentication (Blazor/ASP.NET Core session); document ownership enforced per OwnerUserId in the domain model

### GET /api/editor

**Description**: Authorization-protected editor route group registered by MapEditorEndpoints. Serves inline PDF streams for preview/editing and document content for editing, connecting authenticated users to the server-side PDF manipulation workflow. All routes enforced with RequireAuthorization().

**Source File**: `./src/DocumentConverter.Web/Endpoints/EditorEndpoints.cs`

**Request Format**: Query string parameters (document id, edit mode, page selection)

**Response Format**: application/pdf (inline stream) and application/json (Contracts.Editor DTOs)

**Authentication**: Cookie authentication with RequireAuthorization() applied to the whole /api/editor group

### GET, POST /api/documents (AI / document intelligence surface)

**Description**: AI feature surface registered by MapDocumentIntelligenceEndpoints. Exposes automated categorization, summarization and key-entity extraction for stored documents, mapping to Application.AI services and returning Contracts.AI DTOs. Every route is behind RequireAuthorization().

**Source File**: `./src/DocumentConverter.Web/Endpoints/DocumentIntelligenceEndpoints.cs`

**Request Format**: application/json (document id, operation parameters) and query string parameters

**Response Format**: application/json (Contracts.AI insight DTOs)

**Authentication**: Cookie authentication with RequireAuthorization() applied to the whole group

### POST /account/login

**Description**: Form-based login endpoint registered by MapAccountEndpoints. Reads email/password from HttpContext form data and delegates authentication to ASP.NET Core Identity and Application.Security services. Includes a static UrlIsValid helper that sanitizes redirect/return URLs to prevent open-redirect abuse. Governs session establishment for every other route.

**Source File**: `./src/DocumentConverter.Web/Endpoints/AccountEndpoints.cs`

**Request Format**: application/x-www-form-urlencoded (form fields: email, password, optional returnUrl)

**Response Format**: HTTP redirect to the validated return URL or the login page with error state

**Authentication**: ASP.NET Core Identity (credential submission; establishes the session cookie)

### GET, POST, DELETE /api/processing

**Description**: Processing job API registered by MapProcessingEndpoints, driving background conversion work through Application.Processing services. Approximately ten thin handlers for job submission, status inspection, cancellation and batch results. Uses the named RequireUser authorization policy rather than the default, indicating tighter access control.

**Source File**: `./src/DocumentConverter.Web/Endpoints/ProcessingEndpoints.cs`

**Request Format**: application/json (Contracts.Processing job request/response types)

**Response Format**: application/json (Contracts.Processing job status, result and batch DTOs)

**Authentication**: Cookie authentication with named policy RequireAuthorization("RequireUser")

### POST /api (external AI provider calls)

**Description**: Outbound integration boundary implemented by ExternalAiClient. Builds provider-specific completion requests for OpenAI, Gemini and Anthropic, injects API keys/auth headers, enforces HTTP timeouts and cancellation, parses JSON responses and normalizes error messages. Also exposes PingAsync for connectivity/health checks against configured providers.

**Source File**: `./src/DocumentConverter.Infrastructure/AI/ExternalAiClient.cs`

**Request Format**: application/json (provider-specific completion payload: prompt, model, parameters)

**Response Format**: application/json (provider completion response; parsed and normalized; failures logged via ILogger without leaking payloads)

**Authentication**: Provider API key / bearer token supplied via configuration (per-provider header injection)

### N/A (middleware composition) (internal) IEndpointRouteBuilder / routing pipeline

**Description**: The HTTP request pipeline configured by Program.cs: routing, static files, endpoints, authorization and Blazor/Radzen UI services. Health checks and OpenTelemetry tracing/metrics instrumentation are attached here. Any misconfiguration at this composition root prevents the entire application from starting.

**Source File**: `./src/DocumentConverter.Web/Program.cs`

**Request Format**: HTTP/1.1 and HTTP/2 (Kestrel)

**Response Format**: HTTP responses plus health-check status payloads and OTLP telemetry export

**Authentication**: Pipeline-level middleware ordering: authentication before authorization before endpoint execution

## Router Routes

### /*

**Description**: Global Blazor client-side routing defined in Routes.razor. Instantiates Router against the executing assembly, sets the NotFound page, applies Layout.MainLayout as the default layout, and wraps routed content in AuthorizeRouteView so unauthenticated users never render protected pages. AuthenticationState is cascaded through the tree, and FocusOnNavigate restores focus to the h1 element after each navigation for accessibility.

**Source File**: `./src/DocumentConverter.Web/Components/Routes.razor`

**Parameters**:

- `AppAssembly` (Assembly): Assembly scanned for @page route components (the web application assembly).
- `NotFoundPage` (Type): Component rendered when no route matches the current URI.
- `DefaultLayout` (Type): Layout applied to every routed page (Layout.MainLayout).
### / (root document shell)

**Description**: Top-level HTML document template rendered for every request by App.razor. Emits the <!DOCTYPE html> skeleton, UTF-8 charset, responsive viewport meta, SEO description advertising E-Converter conversion/OCR/AI features, <base href="/"> for client-side routing, favicon SVG plus alternate PNG icon, and the Blazor script bundle mount point. Contains no business logic but affects every page.

**Source File**: `./src/DocumentConverter.Web/Components/App.razor`

**Parameters**:

- `base href` (string): Application base path for Blazor client-side routing; hardcoded to "/".
### /account/*

**Description**: Account area pages under Components/Pages/Account — login, registration, email verification and password recovery. Rendered through the /account endpoint group (AccountEndpoints) which establishes the Identity session that all other routes depend on.

**Source File**: `./src/DocumentConverter.Web/Components/Pages/Account, ./src/DocumentConverter.Web/Endpoints/AccountEndpoints.cs`

**Parameters**:

- `returnUrl` (string): Post-login redirect target, validated by the static UrlIsValid helper to prevent open-redirect abuse.
### /documents/*

**Description**: Document workspace pages under Components/Pages/Documents — folder tree navigation, document listing, upload, version history, recycle bin and per-document dialogs (Components/Dialogs). Backed by the /api/documents and /api/documents AI endpoint groups.

**Source File**: `./src/DocumentConverter.Web/Components/Pages/Documents`

**Parameters**:

- `documentId` (Guid): Identifies the document being viewed; ownership enforced against OwnerUserId.
- `folderId` (Guid?): Optional folder scope for hierarchical browsing.
### /editor/*

**Description**: Server-side PDF editing pages under Components/Pages/Editor — inline PDF rendering (PDF.js from wwwroot/lib/pdfjs), annotation, form filling, redaction, watermarking and signature workflows, with supporting dialogs. Calls the authorization-protected /api/editor endpoint group.

**Source File**: `./src/DocumentConverter.Web/Components/Pages/Editor`

**Parameters**:

- `documentId` (Guid): Document loaded into the editor; only the owner may open it.
### /copilot/*

**Description**: Copilot chat pages under Components/Pages/Copilot — grounded question answering over the user's own document corpus, chat session history, and dossier/report export (XLSX, DOCX, Markdown). Session orchestration is handled by EnterpriseAiChatService.

**Source File**: `./src/DocumentConverter.Web/Components/Pages/Copilot`

**Parameters**:

- `sessionId` (Guid): Identifies a persistent Copilot chat session.
- `scope` (string): Chat scope selector — a folder or a specific document set.
### /jobs/*

**Description**: Processing job monitoring pages under Components/Pages/Jobs — batch submission, progress tracking, priority control, cancel/retry of failed jobs and per-attempt diagnostics using the user-safe error taxonomy. Backed by the /api/processing endpoint group (RequireUser policy).

**Source File**: `./src/DocumentConverter.Web/Components/Pages/Jobs`

**Parameters**:

- `jobId` (Guid): Identifies an individual processing job.
- `batchJobId` (Guid?): Identifies the parent batch aggregation.
### /admin/*

**Description**: Administration pages under Components/Pages/Admin (with Dialogs) — user, role and activation lifecycle management, AI provider configuration (endpoint, proxy, API key parameters), converter catalog availability, storage/security settings and operational health. Intended for administrators only.

**Source File**: `./src/DocumentConverter.Web/Components/Pages/Admin`

**Parameters**:

- `section` (string): Admin subsection selector (users, roles, AI providers, catalogs, settings).
### /tools/*

**Description**: Utility pages under Components/Pages/Tools (with Dialogs) — standalone conversion, PDF compression and auxiliary document utilities exposed to authenticated users.

**Source File**: `./src/DocumentConverter.Web/Components/Pages/Tools`

**Parameters**:

- `tool` (string): Selects the specific tool to load.
### /not-authorized (RedirectToLogin)

**Description**: The NotAuthorized slot of AuthorizeRouteView renders RedirectToLogin, which sends unauthenticated users to the account/login route whenever a protected @page route is requested. This is the enforcement point for the client-side authorization boundary.

**Source File**: `./src/DocumentConverter.Web/Components/Routes.razor`

**Parameters**:

- `returnUrl` (string): Original requested path preserved through the login redirect.
## Integration Suggestions

### Message Queue (AMQP / RabbitMQ)

The web host publishes JobMessage payloads carrying conversion work to the document.processing queue on the document exchange; the DocumentWorker consumes them and runs the decrypt -> hash -> convert -> upload pipeline. ProcessingJob remains the authoritative state aggregate; the broker only handles asynchronous delivery. A NoOpQueuePublisher fallback exists when no broker is configured.

**Example Code**:

```
{
  "RabbitMQ": {
    "Enabled": true,
    "Host": "rabbitmq",
    "Port": 5672,
    "UserName": "econverter",
    "Password": "${RABBITMQ_PASSWORD}",
    "QueueName": "document.processing",
    "ExchangeName": "document"
  }
}
```

**Best Practices**:

- Treat the broker as a transport only; job state, leases and attempts stay in the ProcessingJob aggregate persisted via EF Core.
- Inject RabbitMQ credentials from secret storage rather than appsettings.json (defaults are guest/guest).
- Keep RabbitMQ:Enabled=false in development to exercise the NoOpQueuePublisher and in-process JobProcessorWorker dequeue path.
- Make message consumers idempotent — the documented pipeline (decrypt, hash, convert, upload) can be retried after lease expiry.

### Outbound HTTPS / LLM Provider API

ExternalAiClient builds provider-specific completion requests for OpenAI, Google Gemini and Anthropic, injects API keys and auth headers, enforces HTTP timeouts and cancellation, and normalizes errors. EnterpriseAiChatService constructs Microsoft.Extensions.AI IChatClient instances for Copilot sessions. The AI contract explicitly mandates zero-egress, in-process analysis for private corpora, so provider usage must be an explicit administrative choice.

**Example Code**:

```
// ExternalAiClient: provider dispatch with normalized error handling
var response = await _httpClient.PostAsync(endpoint, content, cancellationToken);
response.EnsureSuccessStatusCode();
var json = await response.Content.ReadAsStringAsync(cancellationToken);
// ExtractErrorMessage(json) surfaces a safe message without leaking payloads
```

**Best Practices**:

- Configure providers and API keys through the Admin UI / options rather than hardcoding them in source.
- Honor the zero-egress architectural constraint: pin document intelligence to the local vector index (HNSW) unless an administrator explicitly enables a remote provider.
- Use PingAsync before switching a provider to verify connectivity and credentials.
- Never log request payloads — ExternalAiClient intentionally logs only normalized error messages via ILogger.

### Relational Database (EF Core / SQL Server)

All persistence flows through AppDbContext, which extends an Identity-enabled DbContext so auth entities share the business schema. Aggregates for AI, Documents, Identity, Processing, Security and System are stored here, with schema defined by configurations and versioned migrations.

**Example Code**:

```
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=sqlserver,1433;Database=EConverterDb;User Id=econverter_app;Password=${DB_PASSWORD};Encrypt=True;TrustServerCertificate=False"
  }
}
```

**Best Practices**:

- Replace the shipped sa credential placeholder with a least-privilege application login injected via ConnectionStrings__DefaultConnection.
- Keep appsettings.Development.json on (localdb)\mssqllocaldb + Trusted_Connection so developers never depend on containerized SQL.
- Apply migrations as a controlled deployment step (the Web project references Microsoft.EntityFrameworkCore.Design for tooling).
- Point the worker and the web host at the same database so job leases, attempts and batch aggregation remain consistent.

### Cryptographic Configuration (AES-256-GCM envelope encryption)

StorageEncryptionOptions binds section Storage:Encryption and holds the Base64-encoded 256-bit Master Key Encryption Key (KEK) used to wrap per-document data encryption keys. Storage writes encrypted envelopes through the StorageProvider abstraction keyed by StorageKey on Document.

**Example Code**:

```
Storage__Encryption__Enabled=true
Storage__Encryption__MasterKey=<base64-encoded-256-bit-KEK>
```

**Best Practices**:

- Inject the master KEK from environment variables or a secret manager; never check key material into appsettings.json.
- Keep the Web host and the DocumentWorker configured with the same KEK, otherwise the worker cannot decrypt what the host wrote.
- Rotate the KEK by re-wrapping DEKs rather than re-encrypting document bodies.
- Monitor Storage:Encryption:Enabled — a silent false disables encryption at rest without any functional error.

### Authentication / Identity (local + Microsoft Entra ID)

AuthenticationType supports Local and EntraId modes. The User aggregate is the stable application identity and authorization keys on the internal Entity.Id rather than the provider subject. ASP.NET Core Identity backs cookie/session state for the interactive Blazor Server UI.

**Example Code**:

```
// AccountEndpoints POST /login
var form = await httpContext.Request.ReadFormAsync();
var result = await _signInManager.PasswordSignInAsync(form["email"], form["password"], ...);
if (UrlIsValid(returnUrl)) return Results.Redirect(returnUrl);
```

**Best Practices**:

- Always route post-login redirects through the UrlIsValid helper to prevent open-redirect abuse.
- Enforce authorization on the internal User.Id, so a change of identity provider does not alter access-control semantics.
- Protect every non-account route with RequireAuthorization(); use the named RequireUser policy for processing operations to keep access control tight.
- Remember the MVP constraint: documents are private to OwnerUserId with no cross-user sharing — do not build sharing surfaces on top of this boundary.

### Storage / Object Store

Document bodies are written as encrypted envelopes through the StorageProvider abstraction (StorageKey on Document) and read back by the worker for hashing, conversion and upload. RootPath controls the local filesystem location; cloud/object-store providers are pluggable adapters.

**Example Code**:

```
{
  "Storage": {
    "RootPath": "/var/lib/econverter/storage"
  }
}
```

**Best Practices**:

- Set Storage:RootPath (or DOCUMENT_STORAGE_ROOT for the worker) to a writable volume that survives container restarts and is excluded from source control.
- Mount the same storage volume into both the web host and the worker container.
- Verify the content hash recorded during the decrypt -> hash -> convert -> upload pipeline before serving a converted artifact.
- Keep the storage backend behind the abstraction so a filesystem provider can be swapped for an object-store provider without touching application code.

### Observability (OpenTelemetry / OTLP)

Program.cs configures OpenTelemetry tracing and metrics with AspNetCore, Http and Runtime instrumentation plus OTLP export, alongside health checks backed by the EF Core health-check package. This is the monitoring boundary for the host.

**Example Code**:

```
builder.Services.AddOpenTelemetry()
    .WithTracing(t => t.AddAspNetCoreInstrumentation().AddHttpClientInstrumentation().AddOtlpExporter())
    .WithMetrics(m => m.AddRuntimeInstrumentation().AddOtlpExporter());
```

**Best Practices**:

- Point the OTLP exporter at a collector via environment configuration, not a hardcoded endpoint.
- Expose health checks (including the EF Core connectivity check) for container liveness/readiness probes.
- Instrument the worker as well so job latency and failure rates are visible end to end.
- Never emit document content or credentials into traces or metric labels.

### Containerized Deployment (multi-stage Docker build)

Both the Web host and the DocumentWorker ship Dockerfiles that restore via layered csproj copies (global.json, Directory.Build.props, Directory.Packages.props and each referenced project) before copying full sources, then publish into a lean runtime image.

**Example Code**:

```
FROM mcr.microsoft.com/dotnet/sdk:10.0 AS build
WORKDIR /src
COPY global.json Directory.Build.props Directory.Packages.props ./
COPY src/DocumentConverter.Domain/*.csproj src/DocumentConverter.Domain/
RUN dotnet restore src/DocumentConverter.Web/DocumentConverter.Web.csproj
COPY . .
RUN dotnet publish src/DocumentConverter.Web/DocumentConverter.Web.csproj -c Release -o /app
```

**Best Practices**:

- Preserve the copy-order of project files before sources so NuGet restore stays cached between builds.
- Keep the central package versions in Directory.Packages.props to avoid version drift across the six projects.
- Run the worker image from mcr.microsoft.com/dotnet/runtime:10.0 (no SDK) to minimize attack surface.
- Supply all secrets (connection strings, RabbitMQ credentials, master KEK, provider API keys) as runtime environment variables, not build-time layers.
